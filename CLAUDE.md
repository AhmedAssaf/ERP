# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

An idea-stage side business named **WaslaBid** (وصلة بد; chosen 2026-09-26, see docs/01 section 1.1): a multi-tenant, white-label tender-to-purchase-order SaaS for Saudi mid-size private companies. Buyers publish RFPs under their own brand, vendors submit sealed technical and financial offers, and offers pass through contracts screening, technical scoring, finance approval, and PO issuance.

The foundation slice is in `src/` (design spec `docs/superpowers/specs/2026-09-26-foundation-design.md`, plan `docs/superpowers/plans/2026-09-26-foundation.md`): solution `WaslaBid.slnx` on .NET 10 (SDK pinned in `global.json`), modules Audit, Tenancy, Identity and Workflow (each a public `.Contracts` project plus an internal implementation), the Blazor host `Platform.Web`, `Platform.Migrator`, `Platform.Shared`, and `Platform.UI` with the Tailwind build; tests in `tests/Platform.UnitTests` and `tests/Platform.IntegrationTests` (Testcontainers, so Docker must be running). Each module ships SQL migrations under `Migrations/` and owns one schema with forced row-level security. Further modules and hosts are created by the first slice that needs them, from a spec and plan, not ad hoc. The admin UI slice (spec `docs/superpowers/specs/2026-09-27-admin-ui-design.md`, plan `docs/superpowers/plans/2026-09-27-admin-ui.md`) adds the module Operations (schema `ops`: health results, incidents, platform audit, active user counts; platform-level, no `tenant_id`), the worker host `Platform.Worker` (Hangfire on PostgreSQL, the health-check and alert job, W-08), the platform console at `https://platform.localhost:8443/platform` (separate Keycloak realm `waslabid-platform`, OTP required; health board, incidents, tenants and jobs: F-51, F-54, F-60; the usage page `/platform/usage` added by W-10: concurrent and active users per tenant, counts only), tenant administration at `/admin/staff` and `/admin/branding` (F-06, F-07, F-02), the admin component subset in `Platform.UI` with `/dev/gallery` (W-06), and `tests/Platform.UITests` (bUnit) with the gallery's golden screenshots in `tests/Platform.UITests/golden/`. The vendor slice (spec `docs/superpowers/specs/2026-09-27-vendors-design.md`, plan `docs/superpowers/plans/2026-09-27-vendors.md`) adds the module Vendors (schema `vendor`: companies, vendor users, documents and the append-only consent ledger under forced row-level security keyed on the vendor company, `app.vendor_company_id`; per-tenant relationships under the tenant policy), vendor pages `/vendor/register`, `/vendor/register/company`, `/vendor`, `/vendor/consent` and `/vendor/join` on tenant hosts, staff pages `/admin/vendors` and `/admin/vendors/{id}`, chunked, ClamAV-scanned uploads (`/vendor/uploads`, ADR-0001), the consent ledger (F-64), and `FileUpload` in `Platform.UI`; `tests/e2e/vendor.mjs` walks it end to end. W-33 (ADR-0013) adds the CR ownership check before a company's first approval and the dispute path: the vendor page `/vendor/dispute`, the console page `/platform/vendors` (check method and dispute review), `Textarea` in `Platform.UI`, and `tests/e2e/ownership.mjs`. The projects under `spikes/` (Arabic PDF, Blazor upload, Elsa W-20, offer-to-Markdown W-22, and `AuditReviewSpike`, the Python demo of the docs/16 idea 7 audit review, with export mappers for SAP, Odoo, Oracle, Microsoft Dynamics, and JSON profiles for NetSuite, ERPNext, Zoho Books and any other ERP; `python test_mappers.py` checks them all end to end) remain throwaway evidence; do not build on them.

Build and verify from the repository root: `dotnet build WaslaBid.slnx -warnaserror`, `dotnet test WaslaBid.slnx` (Microsoft.Testing.Platform runner, set in `global.json`), `dotnet format WaslaBid.slnx --verify-no-changes`. Run locally as described in `docs/07-ways-of-working.md` section 4: migrate and seed with `dotnet run --project src/Platform.Migrator -- --seed-dev`, run `dotnet run --project src/Platform.Web` and `dotnet run --project src/Platform.Worker`, and open `https://acme.localhost:8443` through Caddy; plain `http://localhost:5273` cannot complete an OIDC login. Connection strings, client secrets and storage keys live in user secrets and `infra/compose/.env`, never in the repository (N-10). The spikes target .NET 9; the Blazor spike binds `http://127.0.0.1:5273`, the same port as `Platform.Web`, so do not run both, and needs `ASPNETCORE_ENVIRONMENT=Development` with `--no-launch-profile`. Spike results and decisions are in `docs/06-spike-results.md`.

## Decisions already made (do not reopen without the user)

- Stack: .NET 10, ASP.NET Core modular monolith, Blazor Web App in Interactive Server mode, Tailwind CSS v4 with the in-house `Platform.UI` component library and QuickGrid (ADR-0002, docs/08; MudBlazor was dropped), EF Core with PostgreSQL row-level security, Keycloak 26 Organizations as the tenant model, Hangfire, QuestPDF. Local development runs the dependencies with Docker Compose from `infra/compose` and the app on the host.
- Uploads: vendor files go over chunked HTTP, never through the Blazor circuit (ADR-0001, docs/06).
- Workflow: tenant-configurable definitions with per-tender snapshots are in the foundation from day one (ADR-0003, F-56); the invariants (sealed envelopes, locking, deadlines, audit) are fixed points a definition cannot skip. Our own state machine executes the snapshot, stored as our own versioned JSON (ADR-0004; Elsa was rejected after spike W-20 because Studio cannot serve tenants in Arabic right to left); a refused action never faults a tender. Do not hard-code the approval chain anywhere.
- Edge: Caddy for on-demand TLS and host routing. No API gateway product in version 1. Tenant resolution and rate limiting live in ASP.NET Core middleware. Ocelot is the fallback if a gateway is ever needed.
- AI: assist-only. AI drafts, a named human decides, every AI output is stored with model and prompt version. ADR-0005 (spike W-22, spec `docs/superpowers/specs/2026-09-26-ai-offer-review-design.md`): Claude Sonnet through the Claude API via the Anthropic .NET SDK behind the `Ai` module's port; original PDFs, no OCR; one review per offer at technical opening through the Batch API; off by default, on per tenant with recorded consent to processing outside the Kingdom; financial envelopes never go to a model; price checks (F-48) and integrity comparison (F-49) are code.
- Data residency: everything in a Saudi cloud region.
- Observability (decided 2026-10-01, ADR-0014): Serilog registered only as a `Microsoft.Extensions.Logging` provider (never `UseSerilog()` or `services.AddSerilog()`), the OpenTelemetry SDK for traces and metrics, the OpenTelemetry Collector, Elasticsearch and Kibana 9 on the Basic licence, self-hosted with the app; no Sentry in the pilot; Kibana through an SSH tunnel on the pilot.
- Decision review 2026-09-26 (recorded in docs/02, 05, 09, 11, 12, 13 and ADR-0008 to ADR-0011): company path C (SaaS first, lender decision at year 3); gate 1 before building past the foundation, so the AI offer review plan waits for W-31; no paid hires before paying customers, partners do the early work and put in cash now for equity under a lawyer-drafted agreement (W-32); pricing decided after the interviews; vendors never pay until gate 2; PO scope is PDF plus export, ERP push later as a paid integration, and WaslaBid does not become an ERP; one vendor identity across tenants keyed by CR number, tenders Invited or Open, vendors can invite buyers (ADR-0008); audit bundle F-42, signed award record F-65 and consent ledger F-64 in the MVP; guarantees verified, never issued; the finance licence rules are fixed points (N-11, ADR-0011).
- Product name: WaslaBid, written as one word with a capital B; Arabic logo form وصلة بد. It is the vendor-of-record brand (marketing site, platform admin area, contracts, invoices); tenant-facing screens still carry only the tenant's brand (F-02, docs/08). Code names such as `Platform.UI` stay unchanged. Trademark (SAIP) and domain registration are still to be confirmed.

Still open (see document 02 section 5): the first customer's name (segments are decided) and the pricing model (decided at gate 1, W-31); the observability stack was decided on 2026-10-01 (ADR-0014, item 8). ## Working with the agents and process

`docs/07-ways-of-working.md` is the process document. Seven agents live in `.claude/agents/`: `developer` (one plan task, test first), `reviewer` (read-only, ranked findings against the invariants), `qa-engineer` (tests and scenarios, writes only under `tests/`), `pentester` (adversarial security tests on the local stack, proof tests only under `tests/`), `devops` (`infra/`, CI, Compose), `project-manager` (status from the backlog and git, read-only), `market-analyst` (competitor questions with sources, updates docs/01 and docs/04 only). Route "what is the status" to project-manager and competitor questions to market-analyst. The loop for any implementation task is developer, then reviewer, then qa-engineer, then a human merge; at the end of a slice, and after security-sensitive changes, pentester runs before the merge. Decisions that change a stack row, a diagram, or an invariant get an ADR in `docs/adr/` using `0000-template.md`.

## Conventions

- Documents are numbered `docs/NN-topic.md` and listed in `README.md`; add a line there for every new document.
- Diagrams are Mermaid fenced blocks so GitHub renders them. Validate any new or edited diagram by rendering it with `npx @mermaid-js/mermaid-cli -i file.mmd -o file.png` before committing; broken syntax renders as an error on GitHub.
- Exception, at the user's request (2026-09-26): documents 11, 12, and 13 use PlantUML, not Mermaid. Sources live in `docs/diagrams/11-bmc/`, `docs/diagrams/12-startup/`, and `docs/diagrams/13-investment/` with the rendered PNGs committed beside them; render with `java -jar ~/bin/plantuml.jar -charset UTF-8 -tpng`. No Graphviz is installed, so use mindmap, WBS, activity, legend tables, or `!pragma layout smetana`.
- Quadrant charts need an `%%{init: {"quadrantChart": {...}}}%%` directive with a wider `chartWidth`, or the title is clipped.
- The user and their team prefer diagrams over prose. Lead with a diagram when explaining a flow, architecture, or data model.
- Feature and requirement IDs are stable. Never renumber; append new IDs at the end of the relevant group.
- UI code uses only logical direction utilities (`ms-`, `pe-`, `text-start`, ...); physical ones (`ml-`, `pr-`, `text-left`, ...) fail the lint. Every component is accepted in both directions in the gallery.
- Design specs, when they start, go in `docs/superpowers/specs/` per the brainstorming workflow.

## Publishing workflow

Documents are mirrored as pages in the user's OneNote desktop notebook, section "ERP", automatically: a PostToolUse hook in `.claude/settings.local.json` (this machine only) runs `tools/onenote-hook.ps1` after every Bash call, and when the command contained `git push` it launches `tools/mirror-onenote.ps1` detached. The mirror hashes each numbered document plus `docs/wireframes/README.md` and their referenced images, and rebuilds only the pages whose content changed (delete by title, create, fill via `tools/md2onenote.py`; Mermaid blocks are rendered to PNG first). State and log live in `%LOCALAPPDATA%\erp-onenote`. To force a full rebuild: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\mirror-onenote.ps1 -Force`. OneNote automation works only from Windows PowerShell 5.1, not PowerShell 7. Do not mirror by hand; push and let the hook run. The user asked for this automation on 2026-09-21.
