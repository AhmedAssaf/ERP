# Vendor Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One vendor company across tenants: self-registration with verified email and privacy consent, documents with expiry through chunked, virus-scanned uploads, tenant approval, and the vendor consent ledger.

**Architecture:** New module `Vendors` (schema `vendor`): platform-level company, user, document and consent tables under forced row-level security keyed on the vendor company (second session setting `app.vendor_company_id`), and a tenant-scoped relationship table under the tenant policy. Vendor pages under `/vendor/*` on tenant hosts; staff pages under `/admin/vendors`. Keycloak: tenant realm self-registration with email verification, realm role `vendor`, organization membership per related tenant through the existing admin client.

**Tech Stack:** as the admin slice; ClamAV over TCP `INSTREAM`; MinIO for chunk staging and documents; Testcontainers `clamav/clamav`.

**Spec:** `docs/superpowers/specs/2026-09-27-vendors-design.md` (decisions V-1 to V-14). **ADRs:** 0008, 0010, 0001.

**Style:** like the admin plan: each task gives files, contracts, SQL shape and the exact tests with assertions; the implementer writes code test-first to make them pass and reports every design choice; anything that changes a contract or a V-decision is escalated.

**Conventions:** worktree `C:\Repo\ERP-vendors`, branch `vendors`; commit per task, no AI attribution; test first; `TestContext.Current.CancellationToken`; build `-warnaserror`, tests, `dotnet format --verify-no-changes` green after each task; migrations are new numbered scripts; logical CSS utilities only; Arabic and English strings together; no secret value in any output (N-10); new packages pinned and checked for advisories.

### Task 1: Vendors module, schema and vendor row-level security

**Files:** `src/Modules/Vendors/Platform.Modules.Vendors(.Contracts)` (entry class `VendorsModule` with `AddVendorsModule` and `MigrateAsync`), `Migrations/0001_vendors.sql`, `src/Platform.Shared/Tenancy/VendorAccessor.cs` (set-once, like `TenantAccessor`), `src/Platform.Shared/Data/Migrations/0004_platform_vendor_context.sql` (`platform.current_vendor_company()` reading `app.vendor_company_id` with the same NULLIF rule), `TenantConnectionInterceptor` also sets `app.vendor_company_id` (empty when none), `MigrationRunner` registration, web and worker registration, `ModuleHost`.
**SQL:** tables per spec section 2; forced RLS on `companies` (`id = platform.current_vendor_company()`), `vendor_users`, `documents`, `consent_events` (company policy), `relationships` (`platform.enable_tenant_rls`); `consent_events` insert and select only; `recipients` select only; security-definer functions `vendor.cr_exists(text)`, `vendor.register_company(...)` (creates company, first vendor-admin user, and the relationship for `platform.current_tenant()` in one call, returns the company id), `vendor.related_company(uuid)`, `vendor.related_documents(uuid)` (rows only when a relationship exists for the current tenant), each with pinned `search_path` and `revoke all from public`.
**Tests:**
- `With_no_vendor_context_the_app_role_sees_no_vendor_rows`; `A_vendor_context_sees_only_its_own_company`; `Tenant_b_never_reads_tenant_a_relationship_rows`; `Related_company_returns_rows_only_while_a_relationship_exists`; `Consent_events_are_append_only` (update and delete 42501); extend `TenantTableCatalogTests` so every `vendor.*` table except `recipients` has forced RLS with the tenant or vendor policy; the module boundary tests pass.

### Task 2: Registration, vendor policy and Keycloak (F-11, F-10 part, V-3 to V-7, V-14)

**Files:** realm changes in `waslabid-realm.json` and the test realm copy (`registrationAllowed`, `verifyEmail`, realm role `vendor`; self-registration does not grant `vendor`: the app grants it on company creation through the admin client; Keycloak's registration form limited to email, names and password), `KeycloakAdminClient` additions (`AssignRealmRole`, organization membership reused), `IVendorRegistration` (contracts: `RegisterCompanyAsync(command, userId, email)` returning `Result<Guid>`), validators (CR: 10 digits; VAT: 15 digits starting and ending with 3; names 1-200 with the display-name character rules and `TextSafety`; contact email with the staff email rule), privacy notice text versioned in resources (`Vendor.Privacy.V1` both languages), `Vendor` policy (authenticated, `email_verified`, realm role `vendor`, a `vendor.users` row, member of the host tenant's organization) and middleware that sets `VendorAccessor` after the policy passes, pages `/vendor/register` (redirects to Keycloak registration with the tenant host as redirect) and `/vendor/register/company`.
**Flow detail:** a signed-in, verified user without a `vendor.users` row and without a staff member row may open `/vendor/register/company`; on success: `vendor.register_company`, assign realm role `vendor`, add to the host tenant's organization, audit `vendor.registered` in the tenant's log; then the user must re-sign-in (or refresh the session) so the token carries the role and organization: the page tells them and signs them out through `/account/sign-out` with a return to `/vendor`.
**Tests:** `An_unverified_vendor_cannot_sign_in_until_the_link_is_clicked` (Keycloak plus Mailpit), `A_cr_number_that_is_not_ten_digits_shows_a_specific_error_in_the_vendors_language` (ar and en), `A_vat_number_with_the_wrong_shape_is_refused`, `A_second_registration_with_the_same_cr_is_refused_without_revealing_the_company` (neutral message, audited), `Registration_requires_the_privacy_notice_and_stores_its_version`, `Registering_creates_a_pending_relationship_and_organization_membership_and_audits_it`, `A_vendor_cannot_open_staff_pages`, `A_staff_account_cannot_act_as_a_vendor`, `A_vendor_of_another_tenant_is_challenged_until_it_joins`.

### Task 3: Chunked upload, ClamAV scanning, documents (F-12, V-8 to V-10)

**Files:** `src/Platform.Shared/Scanning/ClamAvScanner.cs` (`IVirusScanner.ScanAsync(Stream)` → Clean, Infected(signature), Unavailable; `INSTREAM` with 64 KB chunks and size limit), upload API in the Web host `src/Platform.Web/Vendor/UploadEndpoints.cs` (`POST /vendor/uploads` {documentType, fileName, size, contentType} → upload id; `PUT /vendor/uploads/{id}/chunks/{n}` 1 MB bodies with SHA-256 per chunk; `POST /vendor/uploads/{id}/complete` {expiresOn} → assemble in MinIO, compute SHA-256, check magic numbers for PDF/PNG/JPEG, scan, then `IVendorDocuments.AddAsync`; all under the `Vendor` policy with antiforgery header), staging in MinIO under `staging/{uploadId}/` with a 24 h cleanup job, `IVendorDocuments` (contracts: `ListAsync`, `AddAsync`), `IVendorCompliance.GetBlockingDocumentsAsync`, Hangfire job retrying `pending_scan` documents every 5 minutes.
**Tests (ClamAV Testcontainer; allow its start-up):** `A_document_is_listed_only_after_a_clean_scan`, `An_infected_upload_is_rejected_deleted_and_audited` (EICAR), `A_scanner_outage_leaves_the_document_pending_and_the_retry_job_lists_it_later`, `A_resumed_upload_after_a_dropped_connection_completes_with_the_same_hash` (send chunks 0-2, restart chunk 2, complete), `A_file_with_the_wrong_type_or_over_10_MB_is_refused`, `Another_vendor_cannot_touch_an_upload_it_did_not_start`, `Expired_and_missing_documents_are_reported_by_name` (both languages), `A_new_document_of_the_same_type_replaces_the_current_one_and_keeps_history`.
