# Admin UI Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A platform console (health board, incidents and alert emails, tenants and jobs) and tenant administration (branding, staff invitations, roles), on the shared component set and a Hangfire worker.

**Architecture:** Builds on the foundation branch. New host `Platform.Worker` (Hangfire server), new module `Operations` (schema `ops`, platform-level tables), additions to Identity (`identity.members`, Keycloak Admin API client) and Tenancy (branding writes), the admin component subset in `Platform.UI`, pages in `Platform.Web` under `/admin/*` (tenant host) and `/platform/*` (platform host).

**Tech Stack:** as the foundation, plus Hangfire 1.8 with Hangfire.PostgreSql, AspNetCore health checks, MailKit, AWSSDK.S3 (MinIO), SkiaSharp, bUnit, Testcontainers generic containers for MinIO and Mailpit.

**Spec:** `docs/superpowers/specs/2026-09-27-admin-ui-design.md`. Section 1 decisions D-1 to D-14 are defaults awaiting the user's confirmation; build them as written.

**How this plan differs from the foundation plan:** written overnight for a much larger slice, so each task gives the files, contracts, SQL, and the exact tests with their assertions, but not every line of implementation code. The implementer writes the code test-first to make those tests pass, and reports every design choice it had to make. Anything that would change a contract or a D-decision is escalated, not decided.

**Conventions (same as the foundation):** branch `admin-ui` (created from `foundation`); commit per task, no AI attribution; test first; `TestContext.Current.CancellationToken` in tests; `dotnet build WaslaBid.slnx -warnaserror`, `dotnet test WaslaBid.slnx`, `dotnet format --verify-no-changes` green after each task; migrations are new numbered scripts, never edits to applied ones; logical CSS utilities only; Arabic and English strings together; no secret value in any output (N-10); versions pinned in `Directory.Packages.props` (check NuGet for the latest stable at the time and record it).

### Task 3: Health checks and the recurring check job (F-51)

**Files:** `src/Modules/Operations/.../Health/` checks for PostgreSQL, MinIO (AWSSDK.S3 `ListObjectsV2` on the bucket, path-style, service URL from config), Keycloak (`GET {Keycloak:ManagementUrl}/health/ready`), ClamAV (TCP `zPING\0` → `PONG`), SMTP (MailKit connect plus `NOOP`), worker (Hangfire `IMonitoringApi.Servers()` heartbeat within 60 s), web host (`GET {Platform:WebHealthUrl}`); a Hangfire recurring job `health-check` every minute that runs all checks with a per-check timeout of 5 s and records the results through `IHealthLog`.
**N-10:** a check's message is the exception type and a fixed sentence (for example "Could not connect to PostgreSQL"), never `ex.Message` for connection or auth errors (those can echo connection strings).

**Tests (integration; Testcontainers MinIO `minio/minio` and Mailpit `axllent/mailpit`; ClamAV replaced by an in-test TCP listener that answers `PONG`, and one that does not answer):**
- `Every_component_reports_healthy_when_its_dependency_is_up` (one test per check, theory).
- `A_dependency_that_is_down_reports_unhealthy_with_a_message_naming_the_component`.
- `A_failure_message_never_contains_a_secret`: PostgreSQL check with a wrong password; the stored message does not contain the password or the connection string.
- `The_check_job_records_one_result_per_component`.
